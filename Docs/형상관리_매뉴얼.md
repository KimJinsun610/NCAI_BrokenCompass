# NCAI_BrokenCompass 형상관리 매뉴얼

본 문서는 NCAI_BrokenCompass Unity 프로젝트의 Git 운영 규칙을 정의합니다.
모든 팀원은 프로젝트에 참여하기 전 본 문서를 반드시 숙지해야 합니다.

**운영 전략 요약**: 원본 에셋(텍스처, 3D 모델, 오디오, 비디오 등)은 용량이 커서 **git에 올리지 않습니다.** 대신 팀 공유 드라이브로 배포하고, git에는 씬(.unity)/프리팹(.prefab)/스크립트/에셋의 `.meta` 파일 등 "가벼운 연결 정보"만 올립니다.

---

## 1. 핵심 원칙 — 왜 `.meta`는 반드시 git에 올려야 하는가

Unity는 씬/프리팹이 에셋을 **파일 경로가 아니라 `.meta` 파일 속 GUID**로 참조합니다.

- 누군가 텍스처를 Unity에 처음 import하면 `텍스처.png.meta`가 자동 생성되고, 씬은 이 GUID로 텍스처를 가리킵니다.
- 원본 파일(`.png`)만 git에서 빼고 `.meta`는 커밋해두면, 다른 팀원이 나중에 같은 경로에 원본을 받아 넣었을 때 **Unity가 기존 `.meta`를 재사용**해서 GUID가 그대로 유지됩니다 → 씬 정상 작동.
- 반대로 `.meta`까지 빠지면, 각자 에셋을 넣을 때마다 Unity가 새 GUID를 만들어버려 씬을 열면 참조가 깨집니다 (핑크 머티리얼, Missing (Mesh/Texture) 등).

**결론: `.meta` 파일은 원본 에셋이 없어도 무조건 git에 커밋합니다.**

## 2. git에 포함되는 것 / 포함되지 않는 것

| 구분 | 예시 | git 포함 여부 |
|---|---|---|
| 씬 | `Assets/Scenes/Main.unity` | ✅ 포함 (텍스트) |
| 프리팹 | `Assets/Prefabs/Player.prefab` | ✅ 포함 (텍스트) |
| 스크립트 | `Assets/Scripts/*.cs` | ✅ 포함 |
| 메타 파일 | `*.meta` (전체) | ✅ **항상 포함** (원본 유무와 무관) |
| 프로젝트 설정 | `ProjectSettings/`, `Packages/` | ✅ 포함 |
| 텍스처/이미지 | `*.png .jpg .psd .tga` 등 | ❌ 공유 드라이브 배포 |
| 3D 모델 | `*.fbx .obj .blend .ma .mb` 등 | ❌ 공유 드라이브 배포 |
| 오디오/비디오 | `*.wav .mp3 .mp4 .mov` 등 | ❌ 공유 드라이브 배포 |
| 폰트/압축파일 | `*.ttf .otf .zip .rar .7z` | ❌ 공유 드라이브 배포 |
| 네이티브 플러그인 | `*.dll .so .a .aar` | ❌ 공유 드라이브 배포 (⚠ 없으면 빌드가 깨질 수 있으니 주의) |
| 캐시/빌드 산출물 | `Library/, Temp/, Obj/, Build/` | ❌ 완전 제외 (재생성됨) |

전체 제외 확장자 목록은 [.gitignore](../.gitattributes)에 정의되어 있습니다. 새 확장자가 필요하면 팀 공지 후 `.gitignore`에 추가하세요.

## 3. 사전 준비 (최초 1회, PC당)

1. Git 설치 확인
2. 저장소 clone
   ```bash
   git clone https://github.com/KimJinsun610/NCAI_BrokenCompass.git
   ```
3. **팀 공유 드라이브 접근 권한 확보** (경로/링크는 팀 채널 공지 참고)
4. Unity 프로젝트 설정 확인 (Edit → Project Settings → Editor)
   - **Asset Serialization → Mode: Force Text** — 씬/프리팹/머티리얼을 텍스트(YAML)로 저장해 diff/merge 가능하게 함
   - **Version Control → Mode: Visible Meta Files** — `.meta` 파일이 탐색기에 노출되어 Git이 추적 가능하게 함
   - 이 값은 `ProjectSettings/EditorSettings.asset`에 저장되어 이미 커밋되어 있으므로, 로컬에서 값이 다르게 보이면 직접 맞춰주세요.

## 4. 새 에셋을 추가할 때 (작업 순서 필수)

### 4-1. 내가 새 에셋을 처음 넣는 경우
1. Unity에 에셋을 import한다 → `.meta`가 자동 생성됨
2. 원본 파일을 **공유 드라이브의 동일한 상대 경로**에 업로드한다
   (예: 프로젝트의 `Assets/Art/Textures/Rock_01.png` → 공유 드라이브의 `Assets/Art/Textures/Rock_01.png`)
3. `.meta` 파일만 git에 add/commit/push한다 (원본은 `.gitignore`에 의해 자동으로 제외됨 — 실수로 원본이 같이 올라가는지 `git status`로 확인)
4. 팀 채널에 "○○ 에셋 추가함, 공유 드라이브 받아가세요" 공지

### 4-2. 다른 팀원이 추가한 에셋을 받는 경우
1. **먼저 `git pull`** → `.meta` 파일부터 받는다
2. 공유 드라이브에서 원본 파일을 받아 **git에 있던 것과 동일한 상대 경로**에 넣는다
3. Unity로 돌아가 정상적으로 로드되는지 확인 (Console에 GUID 충돌/Missing 경고가 없는지)

> ⚠ **순서를 반드시 지키세요.** `.meta`보다 원본을 먼저 넣으면 Unity가 그 자리에서 새 `.meta`(새 GUID)를 만들어버리고, 이후 `git pull`로 팀 공용 `.meta`가 내려와도 이미 로컬에 파일이 존재해 충돌하거나 참조가 어긋날 수 있습니다.

## 5. 씬/프리팹 동시 작업 충돌 방지 — 파일 잠금(File Locking)

씬과 프리팹은 텍스트라도 구조상 병합이 매우 어렵습니다. 여러 명이 같은 씬/프리팹을 동시에 수정하면 충돌이 발생하므로, **작업 시작 전 반드시 잠금을 겁니다.**

```bash
# 작업 시작 전
git lfs lock "Assets/Scenes/Main.unity"

# 현재 잠긴 파일 목록 확인
git lfs locks

# 작업(커밋 + 푸시) 완료 후 잠금 해제
git lfs unlock "Assets/Scenes/Main.unity"
```

- 잠금 기능은 Git LFS의 기능이지만, 이 저장소는 실제 대용량 파일을 LFS 저장소에 올리지 않고 **잠금 용도로만** LFS를 사용합니다 (`.gitattributes`에 `lockable` 속성만 설정됨). 그래도 사용하려면 각 PC에 git-lfs 클라이언트 설치 + 저장소에서 `git lfs install` 1회 실행이 필요합니다.
- 다른 사람이 이미 잠근 파일을 잠그려 하면 실패합니다. `git lfs locks`로 잠근 사람을 확인하고 완료를 기다리거나 직접 조율하세요.
- 잠금은 강제(hard lock)가 아니라 팀 합의 기반 규칙입니다. 잠금을 건 파일은 본인만 수정하고, 완료 즉시 해제해 주세요.
- 자리를 비운 채 잠금이 오래 남아있다면 관리자 권한으로 `git lfs unlock --force "경로"`로 강제 해제할 수 있습니다(팀 논의 후 사용).

## 6. 일반 작업 흐름

```bash
# 작업 시작 전 최신화
git pull

# (씬/프리팹 수정 시) 잠금
git lfs lock "Assets/Scenes/씬이름.unity"

# 작업 후 확인 — 원본 에셋이 실수로 올라가지 않는지 반드시 확인!
git status

git add .
git commit -m "커밋 메시지"
git push

# (씬/프리팹 수정했다면) 잠금 해제
git lfs unlock "Assets/Scenes/씬이름.unity"
```

### 커밋 메시지 규칙 (권장)
- `feat: 기능 추가`
- `fix: 버그 수정`
- `art: 아트 에셋(메타/씬 구성) 추가·수정`
- `chore: 설정/빌드 관련 변경`
- `docs: 문서 변경`

## 7. 절대 하지 말아야 할 것

- `Library/`, `Temp/`, `Obj/`, `Build/`, `Logs/`, `UserSettings/` 폴더를 강제로 add 하지 마세요 (`.gitignore`에 이미 제외됨, Unity가 로컬에서 재생성하는 캐시/빌드 산출물).
- **`.meta` 파일을 임의로 삭제하지 마세요.** 원본 에셋이 로컬에 없어 "안 쓰는 것 같다"고 지워버리면, 다른 팀원 씬의 참조가 깨집니다.
- `.gitignore`/`.gitattributes`를 개인적으로 수정한 채 방치하지 마세요. 팀원마다 추적 대상이 달라지면 "이 파일이 갑자기 git에 잡힌다/안 잡힌다" 하는 혼란이 생깁니다. 변경이 필요하면 공지 후 커밋하세요.
- 원본 에셋(png, fbx, wav 등)을 실수로 커밋하지 마세요. `git add` 전에 항상 `git status`로 확인하는 습관을 들이세요. 이미 `.gitignore`에 등록된 확장자라도, **과거에 이미 git이 추적 중이던 파일**은 gitignore가 적용되지 않으니(§9 참고) 신규 파일부터는 문제없지만 기존 파일은 별도 조치가 필요합니다.
- 씬/프리팹 잠금 없이 장시간 단독 작업하지 마세요. 병합 충돌 시 한쪽 작업이 통째로 유실될 수 있습니다.

## 8. 공유 드라이브 관리

- 공유 드라이브의 폴더 구조는 **Unity 프로젝트의 `Assets/` 이하 상대 경로와 항상 동일하게 유지**합니다. 구조가 어긋나면 팀원이 원본을 엉뚱한 위치에 넣어 GUID 매칭이 실패합니다.
- 에셋을 옮기거나 이름을 바꿀 때는 Unity 에디터 안에서(탐색기에서 직접 하지 말고) 이동/이름변경해 `.meta`가 같이 따라가게 한 뒤, 공유 드라이브의 원본도 동일하게 옮기고 git에는 변경된 `.meta` 경로를 커밋합니다.
- 더 이상 쓰지 않는 에셋은 함부로 삭제하지 말고, 팀 확인 후 Unity에서 삭제(→ `.meta`도 같이 삭제되고 git에 반영됨) + 공유 드라이브에서도 제거합니다.
- 정기적으로(예: 주 1회) 공유 드라이브와 로컬 `Assets/` 폴더를 동기화하는 담당자/루틴을 정해두는 것을 권장합니다.

## 9. 문제 해결 (Troubleshooting)

**Q. `git pull` 받았는데 씬을 열면 텍스처/모델이 비어있다(핑크 머티리얼, Missing)**
→ 정상입니다. 해당 에셋의 `.meta`만 받은 상태고 원본을 아직 공유 드라이브에서 받지 않은 것입니다. §4-2 순서대로 원본을 받아 넣으세요.

**Q. 원본을 받아 넣었는데도 참조가 깨져 있다 (GUID 불일치로 추정)**
→ 원본을 넣기 전에 `.meta`를 pull로 먼저 안 받은 경우입니다. 로컬에 잘못 생성된 `.meta`를 지우고, `git checkout -- "경로/파일명.meta"`로 git 상의 정본 `.meta`를 복원한 뒤 Unity를 다시 열어보세요.

**Q. `git status`에 원본 이미지/모델 파일이 add 대상으로 뜬다**
→ 확인이 필요합니다. `.gitignore`에 해당 확장자가 등록되어 있는데도 뜬다면, **과거에 이미 커밋된 적 있는 파일**일 가능성이 높습니다(`.gitignore`는 신규 파일에만 적용되고, 이미 추적 중인 파일은 계속 추적됨). 이 경우:
```bash
git rm --cached "경로/파일명"
git commit -m "chore: 원본 에셋 git 추적 해제"
```
로 추적만 해제하고(로컬 파일은 유지됨), 이후 다시 안 올라가는지 확인하세요.

**Q. `git lfs lock`이 "you already own a lock" 또는 권한 오류를 낸다**
→ GitHub 저장소에 대한 push 권한이 없으면 잠금이 불가합니다. 저장소 협업자 권한을 확인하세요.

**Q. Force Text로 바꿨는데 이미 저장된 씬 파일이 여전히 바이너리로 보인다**
→ 설정 변경 후 Unity 에디터에서 해당 씬을 열고 다시 저장(Ctrl+S)해야 실제로 텍스트로 재직렬화됩니다.

## 부록: 최초 설정자를 위한 명령어 요약 (참고용, 이미 완료됨)

```bash
git lfs install --local
git lfs track "*.unity" --lockable
git lfs track "*.prefab" --lockable
```

원본 에셋 확장자 제외 목록은 `.gitignore`에 직접 정의되어 있으며(LFS 미사용), 목록은 §2 표를 참고하세요.
