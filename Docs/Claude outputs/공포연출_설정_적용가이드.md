## 0. 공통 구조 — 연출은 두 가지 방식으로 돕니다

**방식 A — 한 번 재생 (Timeline).** 대부분의 연출이 이 방식입니다.

```
[트리거]                                   [연출 본체]                     [내용]
HorrorTriggerZone (구역 진입)  ─┐
HorrorGazeTrigger (바라봄)     ─┼──▶ HorrorEvent.Play() ──▶ PlayableDirector(Timeline)
HorrorAxisLink   (축 구간 진입) ─┤                              ├ Animation 트랙 (문·서랍·weight 등)
디버그 키 / 다른 코드           ─┘                              ├ Audio 트랙
                                                               ├ Activation 트랙 (모형·벌레 켜고 끄기)
                                                               └ Signal 트랙 (메시지 송출 등)
```

- **트리거는 `Play()` 하나만 부릅니다.** 조건이 늘어도 `HorrorEvent`는 고치지 않습니다.
- 연출은 **여러 개가 동시에** 재생될 수 있습니다.

**방식 B — 보는 동안 유지 (2026-09-29 추가).** 바라보는 내내 켜져 있다가 시선을 떼면 꺼집니다. Timeline 없이 컴포넌트가 값을 직접 움직입니다.

```
HorrorGazeHold ── Weight(0~1, 서서히 오르내림) ──┬▶ Volume.weight (화면 톤, §6.5)
                                                └▶ HorrorTreeSway (바라볼 때 더 격하게, §6.6)
```

- ⚠ **한 값에는 한 방식만.** 같은 볼륨 weight를 Timeline과 `HorrorGazeHold`가 함께 움직이면 서로 덮어씁니다.
- 두 방식 모두 **게임 시간** 기준이라 Esc(`GamePause`)를 누르면 소리까지 함께 멈춥니다.

### 0.2 `HorrorEvent` 인스펙터

| 항목 | 뜻 | 주의 |
|---|---|---|
| **Director** | 재생할 PlayableDirector. 비우면 자식에서 찾음 | Playable Asset은 직접 연결 |
| **Play Once** | 한 번만 재생 | 끄면 트리거마다 다시 재생(단, 재생 중에는 무시) |
| **Playback Speed** | Timeline 전체 배속 | 소리도 빨라져 **음이 높아집니다** |
| **Loop Seconds** | Wrap Mode가 **Loop**일 때만. 이 시간 동안 반복한 뒤 돌던 한 바퀴를 끝까지 재생하고 멈춤 | 0 = 무한 반복. 배속과 무관한 실제 초 |
| **After** | 이 연출이 끝난 뒤에만 재생. 시작할 때 앞 연출의 Director를 멈추고 끝 자세를 이어받음 | 같은 오브젝트를 두 Timeline이 번갈아 움직일 때(문 열림 → 쾅) |
| **Wait Until Unseen** | 이 자리가 화면에 안 보일 때까지 기다렸다가 재생 | 인체모형처럼 **시야 밖에서만** 나타나야 할 때. 발밑 Transform을 넣음 |
| **Unseen Box Size** | 시야 판정 상자 크기(발밑 기준 위로) | 기본 0.6 × 1.8 × 0.6 |
| **Max Wait Seconds** | 이만큼 계속 보이면 이번 재생 취소 | 기본 8초 |
| **Lock Player** | 연출 동안 이동·시점 잠금 | 끝나면 자동 해제 |
| **Use Debug Key / Debug Key** | 에디터·개발 빌드에서 이 키로 조건 무시하고 재생 | 출시 빌드에서는 동작하지 않음 |

### 0.3 Director Wrap Mode 선택

| Wrap Mode | 끝나면 | 쓰는 곳 |
|---|---|---|
| **Hold** | 마지막 프레임을 계속 유지 | 문·캐비닛처럼 **끝 자세**를 남겨야 할 때 |
| **None** | Director 정지 → Activation 트랙의 Post-playback State 적용 | 모형·벌레처럼 **끝나면 사라져야** 할 때 |
| **Loop** | 처음부터 반복(`Loop Seconds`로 제한 가능) | 반복 여닫기 |

> ⚠ **Hold + Activation 트랙 함정.** Timeline 길이가 Active 클립보다 짧으면, Hold 상태에서 그 오브젝트가 **영원히 켜져 있습니다.** Post-playback State는 Director가 **정지**할 때만 적용되는데 Hold는 정지하지 않기 때문입니다. 사라져야 하는 연출은 **Wrap Mode를 None**으로 두거나, **Active 클립이 Timeline 끝보다 먼저 끝나게** 하십시오. (`HorrorEvent_Mannequin`이 실제로 이 문제를 겪었고, 지금은 None입니다.)

## 2. 태블릿 지직거림 (TabletGlitch)

### 2.1 구성

| 파일 | 역할 |
|---|---|
| `99 Resources/03 asset/Tablet/TabletScreen.shader` | `Custom/TabletScreen`(URP 언릿). `_Glitch` 0~1 → 주사선·잡음·가로 찢김·깜빡임 |
| `02 Scripts/Tablet/TabletGlitch.cs` | `HUD_Tablet` ▸ `Screen`에 부착. 강도 하나로 화면 바탕과 글자를 함께 깨뜨림 |

**강도 하나(0~1)로만 조절합니다.** 이 스크립트는 누가 강도를 올리는지 알지 못합니다.

| 강도 | 보이는 것 |
|---|---|
| 0 | 멀쩡함(주사선만 은은히) |
| ~0.5 | 잡음·찢김·글자 줄 밀림 |
| 0.55 이상(`corruptionFrom`) | 글자 일부가 기호(▓▒░#…)로 바뀜(최대 15%) |

### 2.2 호출 API

```csharp
TabletGlitch glitch = FindAnyObjectByType<PlayerTablet>()
                        .GetComponentInChildren<TabletGlitch>(true);   // Screen이 꺼져 있어도 찾도록 true

glitch.SetIntensity(0.7f);           // blendSeconds(0.6초)에 걸쳐 부드럽게 올라감
glitch.SetIntensityImmediate(1f);    // 즉시 튐 — 깜짝 연출용
glitch.SetIntensity(0f);             // 끄기 — 글자는 원문으로 정확히 복구됨
```

### 2.3 인스펙터 (`TabletGlitch`)

| 값 | 기본 | 뜻 |
|---|---|---|
| Intensity | 0 | 현재 목표 강도. 플레이 중 슬라이더로 바로 확인 가능 |
| Blend Seconds | 0.6 | 강도 변화 보간 시간 |
| Screen Renderer | (자동) | `Screen/BG`를 찾음 |
| Texts | 7개 | 흔들 글자들. 새 글자를 추가하면 여기에도 넣어야 깨짐 |
| Text Shift | 0.12 | 줄 밀림 폭(**글상자 폭 기준**. fontSize 기준이면 화면 밖으로 튀어나감) |
| Corruption From | 0.55 | 글자 깨짐 시작 강도 |

### 2.4 지금 연결된 곳

- **`_Game/Flow/TabletBridge.cs`(Lee):** 역설 문자가 도착하면 **0.55로 1.4초** 올렸다가 0으로 되돌립니다.
- 그 밖에는 아직 연결이 없습니다.

### 2.5 공포 연출(Timeline)에서 쓰고 싶을 때

`HUD_Tablet`은 플레이어 카메라 아래 있고, 연출 프리팹은 월드에 있습니다. **프리팹 안의 Signal Receiver가 씬의 태블릿을 직접 참조할 수 없습니다.** 선택지는 다음과 같습니다.

- **씬에서만 연결:** 씬에 배치한 인스턴스의 Signal Receiver에 씬의 `TabletGlitch.SetIntensity(float)`를 연결합니다. 빠르지만 프리팹에는 남지 않습니다.
- **(권장, 미구현)** 연출 쪽에 작은 중계 컴포넌트를 두고, 실행 시 `FindAnyObjectByType<PlayerTablet>()`으로 찾아 부르게 합니다. `TabletMessageEventSender`와 같은 방식입니다. 필요하면 만들겠습니다.

### 2.6 주의

- **신뢰 수치로 태블릿을 왜곡하는 안은 폐기됐습니다**(CLAUDE.md §2.8). 원인은 역설 문자·이벤트 등이어야 합니다.
- 글자를 깨는 연출이라 **"누가 마지막에 글자를 쓰는가"**가 중요합니다. `TabletDocument.Render()`는 내용을 쓰기 **전에** `RefreshCleanText()`를 부릅니다. 이 순서를 바꾸면 강도가 높을 때 탭이 안 바뀌는 버그가 재발합니다(2026-09-22 수정).
- 일시정지 중에는 `ViewmodelTime` 자체 시계로 멈춥니다.

| `02 Scripts/Tablet/TabletMessageEventSender.cs` | 인스펙터·Timeline 연결부. `Send()` / `Send(string)` / `Stop()` |

- `HUD_Tablet` 루트에 런타임으로 붙어 코루틴으로 돌기 때문에 씬에 따로 놓을 필요가 없습니다.
- 판정 시스템 문자(`EventBus.MessageSent`)와는 **별개**입니다. 연출 전용이며 판정에 영향을 주지 않습니다.

### 3.2 CSV 규격

| 열 | 내용 | 예 |
|---|---|---|
| A | 이벤트 이름(코드·Timeline에서 부르는 이름) | `Sample_Return` |
| B | 간격(초) | `1.5` |
| C | 메시지. 여러 개는 **`\|`**로 구분 | `경비실로 돌아오십시오\|돌아오십시오` |
| D | 글씨 색 hex(선택) | `#FF3030` · `FF3030` · `#FF303080` · `#F00` |

- 첫 줄은 제목 줄입니다. A열이 비었거나 `#`으로 시작하는 줄은 건너뜁니다.
- D열에 색을 하나 적으면 모든 메시지에 적용됩니다. `|`로 여러 개 적으면 순서대로 적용되고, 모자라면 마지막 색을 이어 씁니다. 빈 칸은 기본색이고, 읽지 못하는 값은 경고와 함께 기본색으로 처리됩니다.
- 따옴표·`""`·칸 안의 줄바꿈·BOM을 처리합니다.

### 3.3 송출 규칙

1. 첫 메시지는 **실행 즉시** 보냅니다.
2. 그 뒤로는 **플레이어가 앞 메시지를 확인해야** B열 간격을 세기 시작합니다. 확인하지 않으면 다음 메시지가 오지 않습니다.
   - 「확인」 = 알람이 꺼지는 조건과 같습니다(태블릿을 들고 메시지 탭을 보는 중이거나, 그 메시지가 읽음 처리됨).
   - 메시지 탭을 보고 있는 동안에는 간격대로 연달아 옵니다.
3. 보낼 때마다 새 id(`event.이름.N`)가 붙어 **매번 알람이 울립니다.**
4. 같은 이벤트를 중복 실행하면 무시되고, 다른 이벤트끼리는 동시에 돕니다.
5. 간격은 게임 시간이라 일시정지 중에는 멈춥니다.

### 3.4 실행 방법 3가지

```csharp
// ① 코드
TabletMessageEvents.Play("Sample_Return");
TabletMessageEvents.Stop("Sample_Return");
```

- **② Timeline:** 연출 오브젝트에 `TabletMessageEventSender` + `Signal Receiver`를 붙입니다. Signal Track에 Signal을 놓고, Receiver에서 `TabletMessageEventSender.Send(string)`을 고른 뒤 이벤트 이름을 적습니다. 이름을 비우고 `Send()`를 고르면 Sender 인스펙터의 `Event Name`을 씁니다.
- **③ 개발자 모드:** `-` 키 → ③ 탭 → 이벤트 목록에서 실행/멈춤, **CSV 다시 읽기**.

### 3.5 CSV 편집 주의 (중요)

- **엑셀에서 「CSV UTF-8(쉼표로 분리)」로 저장하십시오.**
- **한셀로 저장하면 CP949(EUC-KR)로 저장되어** Unity에서 한글이 깨집니다. 에디터에서는 우연히 읽히더라도 빌드에서는 보장되지 않습니다.
- 파일을 연 채로 두면 한셀이 잠가서 Unity가 못 읽을 수 있습니다. 저장 후 닫으십시오.
- 플레이 중에 고쳤다면 개발자 모드의 **CSV 다시 읽기**로 반영합니다.

**여러 프로필 섞기.** 볼륨을 여러 개 두고 각각의 weight가 곧 섞는 비율입니다. 겹치는 항목은 **우선순위가 높은 쪽이 위에 덮입니다.** 예: 채도 Wrongness -20 위에 Suffocate(우선순위 11) -45가 70% 덮여 **-37.5**. 우선순위가 같으면 순서가 매번 달라질 수 있으니 **한 칸씩 다르게** 두십시오.

### 6.5.3 방식 A — Timeline으로 한 번 재생

1. 볼륨들의 **공통 부모**(Director가 있는 연출 오브젝트)에 **Animator**를 붙입니다. Controller는 비워 둡니다.
2. Timeline 창(Window ▸ Sequencing ▸ Timeline) → **+ ▸ Animation Track** → 그 Animator를 바인딩합니다.
3. 트랙의 **● 녹화**를 켜고, 재생 헤드를 옮기며 각 볼륨의 **Weight**를 바꿉니다(값이 이미 같으면 Weight 위 **우클릭 ▸ Add Key**). 녹화를 끕니다.
   - 시각은 Timeline 왼쪽 위 칸에 직접 입력할 수 있습니다(톱니바퀴 ▸ Seconds로 초 단위).
4. 곡선 아이콘으로 그래프를 펼쳐 키를 **Auto/Flat**으로 다듬습니다.
5. **마지막 키는 0이고, Timeline 끝보다 앞에** 있어야 합니다(Hold면 끝 값이 남음).

- **Animator 하나로 자식 여러 개를 움직일 수 있습니다.** 곡선 경로가 자식 이름입니다(`Vol_Wrongness ▸ Volume.weight`).
- 프리팹 모드에는 플레이어 카메라가 없어 미리보기가 안 보일 수 있습니다. 확인은 플레이 모드에서.

예시(인간나무 초기 버전, 지금은 방식 B로 교체됨): `Vol_Wrongness` 0초 0 → 1.2초 **1** → 5초 1 → 6초 0 / `Vol_Suffocate` 같은 시각에 최대 **0.7**. Timeline `05 Animations/Horror/HorrorEvent_HumanTree_ScreenVolumeTimeline.playable`.

### 6.5.4 방식 B — 바라보는 동안 유지 (`HorrorGazeHold`)

볼륨들의 공통 부모에 `HorrorGazeHold`를 붙이고, 볼륨 목록에 넣습니다. Timeline·Animator가 필요 없습니다.

| 값 | 기본 | 뜻 |
|---|---|---|
| Look Point | — | 바라봐야 하는 지점. **움직이는 대상이면 뼈의 자식으로** 두어 따라가게 |
| Look Object | Look Point의 부모 | 여기(와 자식)에 시선이 막히는 것은 가림으로 치지 않음 |
| Max Angle / Max Distance | 12° / 12m | 화면 가운데에서 이 각도 · 이 거리 안이어야 바라본 것 |
| Start Delay | 0.3초 | 이만큼 이어져야 켜지기 시작(스치는 시선 무시) |
| Fade In / Fade Out | 2초 / 1.5초 | 0 ↔ 최대 변화 시간. 양끝은 SmoothStep으로 부드럽게 |
| Volumes | — | 볼륨 + **Max Weight**(섞는 비율) |

- `Weight`(0~1)를 공개하므로 다른 연출이 읽어 쓸 수 있습니다(예: `HorrorTreeSway`, §6.6).
- ⚠ 볼륨 weight를 **직접** 씁니다. 같은 볼륨을 Timeline으로도 움직이면 서로 덮어씁니다.
- 게임 시간 기준이라 일시정지 중에는 그대로 멈춥니다.

### 6.5.5 주의

- **값은 덮어쓰기입니다.** 노출 -3은 "3만큼 어둡게"가 아니라 "실내 2.5를 -3으로 교체"입니다(약 5.5스톱). 프로필을 고칠 때 기본값을 기준으로 생각하십시오.
- 체크하지 않은 항목은 기본 볼륨 값을 그대로 씁니다. 예: `Suffocate`는 노출을 건드리지 않습니다.
- ⚠ **켜고 끌 때 뚝 끊기는 항목이 있습니다.** weight가 0에서 조금만 올라가도 한 번에 바뀌는 것들입니다.
  - **Lens Distortion:** 켜지는 순간 화면을 다시 그리며 픽셀이 밀립니다(실측: weight 0→0.01에서 화면 차이 1.01, 0.01→0.02는 0.00). 그래서 `VP_Horror_Wrongness`의 렌즈 왜곡은 **꺼 두었습니다**(값 0.3은 남음). 기본 볼륨에 렌즈 왜곡이 켜져 있는 곳(실내·실외 0.16)에서는 튀지 않지만, 기본 볼륨이 없는 곳(`testScene` 등)에서는 튑니다. 화면 일그러짐은 ScreenWobble(§1)로 대신하십시오.
  - **켜짐/꺼짐·종류 선택 항목**(Film Grain Type, Vignette Rounded, Tonemapping Mode 등)은 중간값이 없어 weight가 0보다 크면 곧바로 바뀝니다. 가능하면 기본 볼륨과 같은 값으로 두십시오.
  - 확인법: weight 0 / 0.01 / 0.02로 렌더해 **첫걸음 차이가 둘째 걸음보다 훨씬 크면** 튀는 항목이 있는 것입니다. 항목을 하나씩만 켜서 범인을 찾습니다.
- **붉은·주황 틴트 금지.** 조도 축이 색온도(백색→노랑→주황→붉은 잔광)로 표현되므로 헷갈립니다. 색은 채도 빼기·청록 계열로.
- **축이 오를 때마다 켜지 마십시오**(위반 즉시 피드백 금지, CLAUDE.md §2.8). 조우·이벤트에만.
- 태블릿은 후처리 없는 오버레이 카메라가 그리므로 **태블릿 화면은 영향을 받지 않습니다.**

| 값 | 현재 | 뜻 |
|---|---|---|

### 6.6.4 흔들림이 뚝뚝 끊기던 문제 (09-29 수정)

1. 경련 곡선이 사인 반쪽(`sin(πu)`)이라 **시작과 끝의 속도가 최대** → 멈춰 있다 한 번에 튀고 뚝 멈춤. → 꺾임·복귀를 각각 SmoothStep으로 바꿔 **시작·꼭짓점·끝 속도 0**.
2. 바라볼 때 경련이 3배 잦아져 **경련 도중 다음 경련이 시작되며 처음으로 리셋** → 꺾여 있던 가지가 한 프레임에 제자리로 튐. → 경련이 끝나야 다음 간격을 셈.
3. 경련 각도 10° → 6°, 길이 0.22초 → 0.7초로 누그러뜨림.

실측(가지 끝 1m 점, 1/60초 사이 속도 변화 최대): 안 바라봄 3.34 → **0.70** m/s · 바라봄 14.17 → **3.24** m/s (기본 흔들림만 0.16).

> 측정 주의: `Quaternion.Angle`은 약 0.16° 미만을 0으로 반올림해, 고프레임 에디터에서 **가짜 급변**이 잡힙니다. 한 점의 위치를 고정 간격(1/60초)으로 기록해 재십시오.
