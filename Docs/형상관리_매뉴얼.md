# NCAI_BrokenCompass 형상관리 매뉴얼

본 문서는 NCAI_BrokenCompass Unity 프로젝트의 Git / Git LFS 운영 규칙을 정의합니다.
모든 팀원은 프로젝트에 참여하기 전 본 문서를 반드시 숙지해야 합니다.

---

## 1. 사전 준비 (최초 1회, PC당)

### 1-1. Git LFS 설치
- Windows: https://git-lfs.com 에서 설치 파일 다운로드 후 실행
- 설치 확인:
  ```bash
  git lfs version
  ```

### 1-2. 저장소 clone 및 LFS 초기화
```bash
git clone https://github.com/KimJinsun610/NCAI_BrokenCompass.git
cd NCAI_BrokenCompass
git lfs install
git lfs pull
```
- `git lfs install`은 PC(정확히는 전역 Git 설정)당 1회만 하면 되지만, 매번 실행해도 안전합니다(멱등).
- `git lfs pull`을 하지 않으면 LFS 대상 파일들이 포인터 텍스트(예: `version https://git-lfs...`)로만 받아지고 실제 텍스처/모델/오디오 내용은 비어 있습니다. **clone 직후 반드시 실행하세요.**

### 1-3. Unity 프로젝트 설정 확인 (필수)
Edit → Project Settings → Editor 에서 아래 두 항목을 확인/설정합니다.
- **Asset Serialization → Mode: Force Text**
  씬(.unity)/프리팹(.prefab)/머티리얼(.mat) 등을 텍스트(YAML)로 저장해 diff/merge가 가능하게 합니다.
- **Version Control → Mode: Visible Meta Files**
  `.meta` 파일이 탐색기에 노출되어 Git이 추적할 수 있게 합니다.

이 설정은 `ProjectSettings/EditorSettings.asset`에 저장되어 저장소에 커밋되므로, 최초 설정자가 커밋해두면 이후 팀원은 별도 설정이 필요 없습니다. 다만 로컬에서 값이 다르게 표시된다면 위 항목을 다시 확인하세요.

## 2. Git LFS로 관리되는 파일

`.gitattributes`에 정의되어 있으며, 아래 확장자는 커밋 시 자동으로 LFS 저장소로 분리됩니다.

| 분류 | 확장자 |
|---|---|
| 텍스처/이미지 | png, jpg, jpeg, tga, tif, tiff, psd, psb, exr, hdr, bmp |
| 3D 모델 | fbx, obj, blend, max, ma, mb, dae, 3ds |
| 오디오 | wav, mp3, ogg, aiff, flac |
| 비디오 | mp4, mov, avi, webm |
| 폰트 | ttf, otf |
| 압축파일 | zip, rar, 7z |
| 네이티브 플러그인 | dll, so, a, aar |
| DCC 툴 포맷 | sbsar(Substance), spp(Substance Painter) |

**씬(.unity) / 프리팹(.prefab)은 LFS로 넣지 않습니다.** Force Text 직렬화로 관리하여 diff가 가능하도록 유지하고, 대신 아래 3장의 파일 잠금(lock) 기능으로 동시 수정 충돌을 예방합니다.

### 새로운 확장자를 추가해야 할 때
```bash
git lfs track "*.확장자"
git add .gitattributes
git commit -m "chore: XXX 확장자 LFS 추적 추가"
```
- `.gitattributes`는 팀 공용 설정 파일입니다. 임의로 라인을 삭제하지 말고, 추가가 필요하면 PR/공지를 통해 팀 전체에 알리고 커밋하세요.
- 이미 LFS 등록 전에 일반 Git으로 커밋된 대용량 파일이 있다면 `git lfs migrate import --include="*.확장자"`로 기존 히스토리까지 이전이 필요할 수 있습니다 (히스토리를 재작성하므로 팀 전체 조율 후 진행).

## 3. 씬/프리팹 동시 작업 충돌 방지 — 파일 잠금(File Locking)

씬과 프리팹은 텍스트라도 구조상 병합이 매우 어렵습니다. 여러 명이 같은 씬/프리팹을 동시에 수정하면 충돌이 발생하므로, **작업 시작 전 반드시 잠금을 겁니다.**

```bash
# 작업 시작 전
git lfs lock "Assets/Scenes/Main.unity"

# 현재 잠긴 파일 목록 확인
git lfs locks

# 작업(커밋 + 푸시) 완료 후 잠금 해제
git lfs unlock "Assets/Scenes/Main.unity"
```

- 다른 사람이 이미 잠근 파일을 잠그려 하면 실패합니다. 이 경우 `git lfs locks`로 잠근 사람을 확인하고 완료를 기다리거나 직접 조율하세요.
- 잠금은 강제(hard lock)가 아니라 팀 합의 기반 규칙입니다. 잠금을 건 파일은 반드시 본인만 수정하고, 완료 즉시 해제해 주세요.
- 부득이하게 본인이 자리를 비운 채 잠금이 오래 남아있다면, 관리자 권한으로 `git lfs unlock --force "경로"`로 강제 해제할 수 있습니다(팀 논의 후 사용).

## 4. 일반 작업 흐름

```bash
# 작업 시작 전 최신화
git pull

# (씬/프리팹 수정 시) 잠금
git lfs lock "Assets/Scenes/씬이름.unity"

# 작업 후 확인
git status
git lfs status        # LFS 대상 파일이 정상적으로 포인터로 처리되는지 확인

git add .
git commit -m "커밋 메시지"
git push

# (씬/프리팹 수정했다면) 잠금 해제
git lfs unlock "Assets/Scenes/씬이름.unity"
```

### 커밋 메시지 규칙 (권장)
- `feat: 기능 추가`
- `fix: 버그 수정`
- `art: 아트 에셋 추가/수정`
- `chore: 설정/빌드 관련 변경`
- `docs: 문서 변경`

## 5. 절대 하지 말아야 할 것

- `Library/`, `Temp/`, `Obj/`, `Build/`, `Logs/`, `UserSettings/` 폴더를 강제로 add 하지 마세요 (`.gitignore`에 이미 제외되어 있음, Unity가 로컬에서 재생성하는 캐시/빌드 산출물).
- `.gitattributes`를 개인적으로 수정한 채 방치하지 마세요. 다른 팀원의 워킹 디렉터리와 LFS 추적 대상이 달라지면 `이 파일이 갑자기 텍스트/바이너리로 바뀌어 보이는` 문제가 발생합니다.
- 대용량 파일을 LFS 등록 없이(`.gitattributes` 반영 전) 커밋하지 마세요. 이미 일반 Git 오브젝트로 커밋되면 저장소 용량이 그대로 남아 나중에 히스토리 재작성이 필요해집니다.
- 씬/프리팹 잠금 없이 장시간 단독 작업하지 마세요. 병합 충돌 시 한쪽 작업이 통째로 유실될 수 있습니다.

## 6. LFS 저장 용량/대역폭 관리

GitHub의 Git LFS 무료 한도는 저장소당이 아닌 **계정(또는 조직)당 1GB 저장공간 / 월 1GB 다운로드 대역폭**입니다. 대용량 에셋이 많은 프로젝트 특성상 무료 한도를 빠르게 초과할 수 있습니다.

- 사용량 확인: GitHub 저장소 → Settings → Billing and plans → Git LFS Data (또는 계정 Billing 설정)에서 확인 가능합니다.
- 한도 초과가 예상되면 GitHub의 Data Pack(유료 추가 용량)을 구매하거나, 원본 소스(FBX, PSD 등 원본 작업 파일)는 별도 클라우드 스토리지(Drive, Perforce 등)에 두고 Git 저장소에는 익스포트된 최종 에셋만 커밋하는 방식도 고려할 수 있습니다.
- 계정 소유자(레포 관리자)가 주기적으로(예: 월 1회) 사용량을 확인하고 팀에 공유하는 것을 권장합니다.

## 7. 문제 해결 (Troubleshooting)

**Q. clone 했는데 텍스처/모델이 깨져 보이거나 파일 크기가 이상하게 작다 (몇 KB)**
→ `git lfs pull`을 실행하지 않은 것입니다. 프로젝트 루트에서 `git lfs pull` 실행.

**Q. 커밋하려는데 "This exceeds GitHub's file size limit of 100.00 MB" 오류가 뜬다**
→ 해당 확장자가 `.gitattributes`에 LFS로 등록되어 있는지 확인하세요. 등록되어 있는데도 발생한다면 `git lfs install`이 안 되어 있거나, 파일을 add하기 전에 `.gitattributes` 변경사항이 먼저 커밋/반영되지 않은 경우입니다.

**Q. `git lfs lock`이 "you already own a lock" 또는 권한 오류를 낸다**
→ GitHub 저장소에 대한 push 권한이 없으면 잠금이 불가합니다. 저장소 협업자 권한을 확인하세요.

**Q. Force Text로 바꿨는데 이미 커밋된 씬 파일이 여전히 바이너리로 보인다**
→ 설정 변경 후 Unity 에디터에서 해당 씬을 열고 다시 저장(Ctrl+S)해야 실제로 텍스트로 재직렬화됩니다. 필요한 파일들을 한 번씩 열었다 저장한 뒤 재커밋하세요.

## 8. 대용량 3rd-party 에셋(에셋스토어 등) 관리 정책

`Assets/NOT_Lonely` 같은 대용량 에셋스토어 패키지는 **git/LFS로 공유하지 않습니다.**
GitHub Git LFS 무료 한도(계정당 저장 1GB / 월 다운로드 1GB)로는 이런 패키지 하나도 감당이 안 되기
때문입니다. (`horror house/.gitignore`에 `/Assets/NOT_Lonely/`로 이미 제외 처리되어 있습니다.)

**원칙**
- 원본 그대로인 3rd-party 패키지 폴더는 통째로 `.gitignore` 처리하고, 팀원이 각자 로컬에
  **동일 버전**으로 준비합니다 (에셋스토어에서 직접 임포트하거나, 아래처럼 공유 스토리지에서 받기).
  같은 버전이어야 패키지 내부 파일들의 GUID가 동일해서 씬/프리팹 참조가 깨지지 않습니다.
- 새로운 대용량 패키지를 추가로 들여올 때도 같은 방식으로 `.gitignore`에 한 줄 추가하세요.
  ```
  /Assets/새패키지폴더명/
  /Assets/새패키지폴더명.meta
  ```
- 패키지 안의 파일을 수정해서 쓰는 경우(예: 텍스처를 직접 리터치)는 더 이상 "원본 그대로"가
  아니므로, 수정한 파일만 `Assets/_Game/` 쪽으로 복사해서 오버라이드하거나 별도로 git에
  추적되게 예외 처리하세요 (`.gitignore`에 `!경로` 형태로 추가).
- 팀원이 패키지 파일을 직접 못 구하는 상황이라면, 필요한 파일만 추려서(용량 절감) zip으로 묶어
  Google Drive 등 별도 클라우드에 올려두고 이 문서에 다운로드 링크와 압축 해제 위치를 적어두세요.

## 9. 우리가 만드는 콘텐츠는 `Assets/_Game/` 아래에

3rd-party 에셋과 우리가 직접 만드는 게임 콘텐츠를 명확히 구분하기 위해 아래 폴더 구조를 씁니다.
`_Game`처럼 언더스코어를 붙이면 Unity 프로젝트 창에서 항상 맨 위에 정렬되어 찾기 쉽습니다.

```
Assets/_Game/
├── Scenes/            # 작업용 씬 (예: DemoScene을 복사해서 만든 우리 게임 씬)
├── Scripts/            # C# 스크립트
├── Prefabs/            # 우리가 만든 프리팹, 또는 벤더 프리팹의 Variant
├── Materials/
├── Art/                 # 직접 제작/구매해서 커스텀한 텍스처, 모델 등
├── Audio/
└── ScriptableObjects/
```

이 폴더는 `.gitignore` 예외 없이 전부 git으로 추적되며(대용량 바이너리는 기존 `.gitattributes`
LFS 규칙이 그대로 적용됩니다), 씬/프리팹 잠금 규칙(3장)도 동일하게 적용됩니다.

**작업 흐름 예시**
1. `Assets/NOT_Lonely/HQ_AbandonedSchool/DemoScene/DemoScene.unity`를
   `Assets/_Game/Scenes/`로 복사(Ctrl+D 또는 Duplicate) 후 이름을 바꿔서 작업 시작.
   (씬 파일 자체는 어디로 옮기거나 복사해도 안전합니다 — 안에서 참조하는 벤더 에셋들은
   GUID로 연결되어 있어서 벤더 폴더가 로컬에 있기만 하면 계속 정상 작동합니다.)
2. 새 스크립트는 `Assets/_Game/Scripts/`에 작성.
3. 씬에서 새로 필요한 에셋(직접 제작했거나 작은 규모로 구매한 것)은 `Assets/_Game/Art/` 등에
   추가 — 이건 `.gitignore` 대상이 아니라 그대로 git/LFS로 공유됩니다.
4. 벤더 프리팹을 커스터마이징해야 하면 원본을 고치지 말고 Prefab Variant를 만들어
   `Assets/_Game/Prefabs/`에 저장하세요 (벤더 폴더는 언제든 재설치될 수 있는 "읽기 전용"으로 취급).
