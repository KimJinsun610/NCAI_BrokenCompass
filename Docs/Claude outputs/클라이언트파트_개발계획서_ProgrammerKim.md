## 2. 인터페이스 계약 — 이 문서에서 가장 중요한 절

두 사람이 서로를 기다리지 않게 하는 장치입니다. **W1 첫날에 Lee가 아래를 빈 껍데기로 커밋**하고, 그때부터 양쪽이 독립적으로 갑니다.

### 2.1 Kim이 구현하는 인터페이스

```csharp
// Lee가 정의 → Kim이 공간마다 구현
public interface ISpacePresenter {
    SpaceId Space { get; }
    void OnBandChanged(FearAxis axis, Band from, Band to);
    void OnBandProgress(FearAxis axis, float t01);   // 밴드 내 연속량 (색온도 보간)
    void ResetForNewDay();
}

// Lee가 정의 → Kim이 태블릿 UI로 구현
public interface IDocumentView {
    void Render(IReadOnlyList<RuleEntry> rules, ClauseZero clause, int trustBand);
    void Open();  void Close();
    bool IsOpen { get; }
}

public readonly struct RuleEntry {
    public readonly string Text;       // 지침록 원문 그대로
    public readonly FontVariant Font;  // ★ 신뢰 축 — 어느 항목을 다른 서체로
    public readonly bool IsErased;     // 축 70+ 에서 사라진 규칙
}
```

```csharp

EventBus.DayEnded      += (summary) => ...;
EventBus.PhoneIncoming += (directive) => ...;
EventBus.AxisCritical  += (axis) => ...;   // 사망 연출 트리거
```

### 2.3 🔑 `DebugAxisDriver` — 병렬 작업의 핵심

**Lee가 W1에 제공하는 디버그 패널입니다.** 축 4개를 슬라이더로 직접 조작합니다.

이게 있으면 Kim은 **Lee의 판정 시스템이 완성되기 전에 모든 구간 연출을 만들고 검증할 수 있습니다.** 슬라이더를 0→100으로 끌면서 등이 순서대로 꺼지는지, 오디오가 바뀌는지, 물건이 움직이는지를 눈으로 확인하는 거죠.

> **이 하나로 W1~W4에 Kim이 Lee를 기다리는 시간이 0이 됩니다.** 반대로 이게 없으면 Kim은 "규칙을 실제로 어겨야" 연출을 볼 수 있어서 반복 속도가 10배쯤 느려집니다. W1 최우선 요청 항목입니다.

빌드 제외 심볼(`#if UNITY_EDITOR || NIGHTDUTY_DEBUG`)로 감싸서 제출 빌드에는 안 들어가게 합니다.

### 3.2 🔴 씬 락 프로토콜 — 두 사람 중 Kim이 씬을 훨씬 많이 만집니다

`.unity`와 `.prefab`은 LFS lock 대상입니다. **Kim의 작업 대부분이 여기에 걸립니다.**


**팀 합의 사항으로 제안합니다.**

| 규칙 | 내용 |
|---|---|
| 씬 락은 **당일 반납** | 하루를 넘겨 잡고 있지 않기. 퇴근 전 unlock |
| 아트팀과 시간대 분리 | 같은 씬을 Kim(배치·연출)과 아트(라이팅·소품)가 동시에 만짐. **요일 또는 오전/오후로 나누기** |

**`Assets/NOT_Lonely/`는 gitignore입니다.** `git add` 시도 금지, Git 클라이언트의 **"Discard All"은 이 폴더를 통째로 삭제**합니다. 절대 쓰지 마세요.

## 4. 작업 영역별 설계

### 4.1 태블릿 지침록 — 최우선 작업

**W3 검증 게이트의 통과 지표 중 하나가 「지침록을 순찰 중 2회 이상 재열람」입니다.** 즉 지침록 UI는 W3까지 스텁이 아니라 **진짜로 완성돼 있어야** 게이트를 판정할 수 있습니다. Kim의 W2 최우선 항목입니다.

기획서 UI 초안(태블릿 목업)의 요소:

```
┌─────────────────────────────────────┐
│ 발신                    시설관리팀   │
│ 문서                  NB-217-01 · 발행 21:40 │
├─────────────────────────────────────┤
│ 근무일        한계       근무 시간   │
│  1 / 5      01:47      00:00 - 04:00 │
├─────────────────────────────────────┤
│ 근무 수칙                            │
│ 1  고성을 낼 때는 문을 닫으십시오.    │
│ 2  복도를 지나던 중 문이 열린다면...  │
│ …                                    │
│ §0 (8pt, 하단 여백)                  │  ← 본문보다 확연히 작게
├─────────────────────────────────────┤
│ 본 문서는 금일 근무에 한해 유효합니다.  6 항목 │
└─────────────────────────────────────┘
```

**구현 요점 4가지**

1. **§0 조판** — 본문보다 확연히 작은 글자(8pt 상당), 스크롤 하단 배치. 기획 의도가 「대부분의 플레이어는 Day 2 첫 충돌을 겪은 뒤에야 이 줄을 발견한다」입니다. **너무 잘 보이면 게임이 망가지고, 너무 안 보이면 부당해집니다.** W6 테스트에서 발견율 60% 미만이면 Day 1에 프린터 확대 컷 추가 — 그 대비로 **폰트 크기를 인스펙터 노출 값으로** 빼두세요.

2. **서체 변조 (신뢰 축)** — TMP Font Asset **3~4종**이 필요합니다.

   | 신뢰 구간 | 표현 |
   |---|---|
   | 0~49 | 전 항목 동일 서체 |
   | 50~74 | **1개** 항목이 다른 서체 |
   | 75~89 | **2~3개** |
   | 90~100 | **3~4개** |

   차이는 미세해야 합니다 — 자간이 살짝 넓거나, 획 두께가 미묘하게 다르거나. **"다른 폰트다"가 아니라 "뭔가 이상하다"** 수준. 명조↔고딕처럼 확 다르면 안 됩니다. 어느 항목을 바꿀지는 Lee가 `RuleEntry.Font`로 넘깁니다.

3. **사라지는 규칙** — 축 70 이상에서 규칙 1줄이 인쇄되지 않은 것처럼 사라집니다(`IsErased`). **줄을 지우지 말고 번호를 유지**하세요. 「3번 다음이 5번」이 되어야 플레이어가 눈치챕니다.

4. **열람 중에도 시간이 흐릅니다.** 일시정지 금지. TAB으로 열고 닫기.

### 4.2 순찰 HUD — 요소가 4개뿐입니다

잔여 시간 · 체크리스트 · 지침록 단축키 · 손전등 상태. **끝입니다.**

> **스탯 게이지도, 위반 알림도 만들지 마세요.** 이게 이 게임의 설계 핵심입니다. 플레이어는 자기가 규칙을 어겼다는 사실 자체를 모른 채 환경이 변해가는 것만 봅니다. UI가 친절해지는 순간 공포가 사라집니다.

유예 시간(2~4초) 동안 아무 피드백도 없어야 한다는 것도 같은 이유입니다.

**단 하나의 예외** — 준수가 `Attempt` 모드로 확정될 때 지침록 해당 줄에 **아주 약한 시각 변화**(자간 미세 축소 등)를 줍니다. "됐다"고 알려주진 않되, 반복 플레이어가 눈치챌 수 있는 층위. 판정서 §1.1의 부당함 제거 장치입니다. 이건 Lee와 W4에 함께 튜닝합니다.

### 4.5 공간 연출 — Kim의 주 작업량 (40 상태)

| 축 | 실작업 | 방식 |
|---|---:|---|
| 조도 | **5** | 공통 색온도 표 1개 + 공간별 등 개수 4개 |
| 청각 | **20** | 공간×구간 개별. `AudioSequenceSO` 값 입력 |
| 배치 | **14** | 하위 2구간 공식화 + 상위 3구간 개별 12 + 공통 2 |
| 신설 | **1** | 복도 배치 75~89 「교실 문이 세 개」 |

**조도가 거의 공짜입니다.** `LampFluoBuiltinA` / `_ON` / **`_flicker`** 3종이 에셋에 이미 있어서 프리팹 스왑 + Light 색온도 설정으로 끝납니다.
